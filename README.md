# pkgj- : PKGj внутри Vita3K Plus (Android, arm64)

## Цель

Чтобы в эмуляторе **Vita3K Plus** на Android работал **полный цикл PKGj**:

1. запуск `pkgj.vpk` и интерфейс;
2. загрузка списков контента из сети;
3. **скачивание** PKG;
4. **установка** скачанного PKG (как это делает консоль);
5. **запуск** установленного приложения из LiveArea эмулятора.

Целевое устройство: **Samsung Galaxy S22+ (Exynos 2200, GPU Xclipse 920)**, Android, только **arm64-v8a**.

## Что в репозитории

| Путь | Что это |
|---|---|
| `vita3k/`, `android/`, `cmake/`, `data/`, ... | Полный исходный код Vita3K Plus 1.4 (Corrected). Его мы патчим |
| `vita3k-plus-orig-readme/README-upstream.md` | Оригинальный README эмулятора |
| `.github/workflows/android-arm64.yml` | Быстрая CI-сборка только под arm64 |
| `test/pkgj.vpk` | Тестовое приложение PKGj v0.61 |

## Что выяснено по исходникам и VPK

- `pkgj.vpk` это PKGj v0.61 (TITLE_ID `PKGJ00000`). `eboot.bin` сжатый SELF, формат для Vita3K обычный.
- **`ScePromoterUtil` полностью заглушка**: все 13 функций (`Init`, `Exit`, `GetState`, `GetResult`, `PromotePkg`, `PromotePkgWithRif`, `CheckExist`, `DeletePkg`, ...) возвращают `UNIMPLEMENTED()`. Файл: `vita3k/modules/ScePromoterUtil/ScePromoterUtil.cpp`. PKGj ставит скачанные PKG именно через него, значит это **главный блокер** шагов 4 и 5.
- Модули `SceHttp`, `SceSsl`, `SceNet`, `SceSqlite`, `SceNpDrm`, `SceAppUtil`, `SceShellSvc` существуют; в `SceHttp` около 60 функций ещё заглушки, нужно проверить, какие вызывает PKGj.
- В `android/app/build.gradle` уже стоит `abiFilters "arm64-v8a"`. x86_64 в этой сборке сломан и не нужен.
- Папка `external/` в исходном архиве была пустой (в архивах GitHub нет сабмодулей), теперь они подключены (шаг 0).

## План работ

### Шаг 0. Подготовить репозиторий к сборке
- [x] Сабмодули подключены как настоящие git submodules (28 штук, `.gitmodules` + gitlink-и в `external/`).
- [x] `pkgj.vpk` лежит в `test/pkgj.vpk`.
- [x] Автозапуск CI по пушу включён (игнорируются `*.md`, `docs/`, `_readme/`).
- [ ] Первая сборка зелёная.

**Как подобраны версии сабмодулей.** Архив Vita3K из GitHub не содержит сабмодулей, поэтому SHA взяты из истории апстрима `Vita3K/Vita3K`. Plus 1.4 собран на апстриме до обновления зависимостей от 2026-07-26: файлы `vcpkg.json`, `external/CMakeLists.txt`, `miniz`, `cli11`, `ddspp` совпадают с апстримом того периода. Поэтому взят коммит `5ded8c7` (2026-07-24). Свежий master не подходит: там уже другая файловая система (std::filesystem вместо Boost) и новые версии зависимостей. Это вывод по совпадению файлов, а не по записи самого Plus. Если сборка упадёт на несовпадении API, первым делом проверять версии `dynarmic`, `sdl`, `ffmpeg`.

## Ускорение CI

Сделано сразу:
- CI запускается по пушу, но не при изменении `*.md`, `docs/`, `_readme/`.
- Только **один job: Android arm64-v8a**. Убраны Windows, Linux, macOS, CodeQL, format и labeler.
- **Только arm64-v8a**, без x86/x86_64 (на уровне Gradle это уже было).
- `fetch-depth: 1` (без истории).
- Кэш vcpkg-зависимостей и ccache (до 2 ГБ), кэш Gradle.
- `concurrency` с `cancel-in-progress`: новый пуш отменяет предыдущую сборку.
- Без ключа подписи собирается `Reldebug`: для тестов подпись не нужна.

Сделаем позже, если сборка всё ещё долгая:
- Отключить в CMake для Android всё лишнее: тесты (googletest), tracy, десктопные утилиты, gdbstub.
- Сборка только изменённых модулей благодаря ccache; для итераций по ScePromoterUtil основная часть сборки возьмётся из кэша.

## Правила работы

- Один шаг плана, один (или несколько) коммитов.
- Перед каждым шагом отмечать выполненное галочками в этом файле.
- Все правки эмулятора живут в `vita3k/` в этом репозитории.
