# pkgj- : PKGj внутри Vita3K Plus (Android, arm64)

## Цель

Чтобы в эмуляторе **Vita3K Plus** на Android работал **полный цикл PKGj**:

1. запуск `pkgj.vpk` и интерфейс;
2. загрузка списков контента из сети;
3. **скачивание** PKG;
4. **установка** скачанного PKG (как это делает консоль);
5. **запуск** установленного приложения из LiveArea эмулятора.

Целевое устройство: **Samsung Galaxy S22+ (Exynos 2200, GPU Xclipse 920)**, Android, только **arm64-v8a**.

## Что выяснено по исходникам и VPK

- `pkgj.vpk` это PKGj v0.61 (TITLE_ID `PKGJ00000`). `eboot.bin` сжатый SELF, формат для Vita3K обычный.
- **`ScePromoterUtil` полностью заглушка**: все 13 функций (`Init`, `Exit`, `GetState`, `GetResult`, `PromotePkg`, `PromotePkgWithRif`, `CheckExist`, `DeletePkg`, ...) возвращают `UNIMPLEMENTED()`. Файл: `vita3k/modules/ScePromoterUtil/ScePromoterUtil.cpp`. PKGj ставит скачанные PKG именно через него, значит это **главный блокер** шагов 4 и 5.
- Модули `SceHttp`, `SceSsl`, `SceNet`, `SceSqlite`, `SceNpDrm`, `SceAppUtil`, `SceShellSvc` существуют; в `SceHttp` около 60 функций ещё заглушки, нужно проверить, какие вызывает PKGj.
- В `android/app/build.gradle` уже стоит `abiFilters "arm64-v8a"`. x86_64 в этой сборке сломан и не нужен.
- Папка `external/` в исходном архиве была пустой (в архивах GitHub нет сабмодулей), теперь они подключены (шаг 0).

## План работ

### Шаг 0. Подготовить репозиторий к сборке
- [x] Сабмодули подключены как настоящие git submodules (28 штук, `.gitmodules` + gitlink-и в `external/`).
- [x] `pkgj.vpk` лежит в `test/pkgj.vpk`.
- [x] Автозапуск CI по пушу включён (игнорируются `*.md`, `docs/`, `_readme/`).
- [x] Первая сборка зелёная (с третьей попытки).
  - Сборка 1 (24 мин): упала на отсутствующем `vita3k/util/include/util/fork_build.h`. Этого файла нет в архиве Plus, он восстановлен по символам из `logging.cpp` (`FORK_BUILD_SEQ`, `FORK_BUILD_CHANGES`). Остальные локальные `#include` проверены скриптом, других пропавших файлов не найдено.
  - Сборка 2 (4 мин): упала в `vita3k/codec/src/atrac9.cpp`, функции `Atrac9DecodeBounded` нет в апстримном LibAtrac9 (это доработка форка Plus). Реализована в `atrac9.cpp` как обёртка над `Atrac9Decode` с копией данных, дополненной нулями.
  - Сборка 3: **успешна**. APK ставится на S22+, PKGj v0.61 запускается и показывает интерфейс. Проблемы из первого запуска (лог `vita3k.log`):
    1. Красная плашка `NoNpDrm not found`: PKGj ищет модуль NoNpDrm через `_vshKernelSearchModuleByName`, эмулятор отвечал «модуля нет». Исправлено: для имени `NoNpDrm` возвращается положительный id (Vita3K и так ставит такой контент нативно).
    2. `can't get list: sceHttpSendRequest failed: 0x80431082 Request blocked`: сеть до соединения не доходит. В логе `sceNetCtlInetGetInfo` не отдаёт настройку HTTP-прокси (структура остаётся неинициализированной, libhttp может решить, что прокси включён). Исправлено: прокси = выключен. Это гипотеза по логу, подтверждение даст следующий тест. Также `sceNetResolverDestroy` больше не заглушка, в лог пишется результат разрешения имён.
    3. PKGj теперь **встроен в APK** (`android/app/assets/preinstalled/pkgj.vpk`) и ставится автоматически при первом запуске эмулятора.

**Как подобраны версии сабмодулей.** Архив Vita3K из GitHub не содержит сабмодулей, поэтому SHA взяты из истории апстрима `Vita3K/Vita3K`. Plus 1.4 собран на апстриме до обновления зависимостей от 2026-07-26: файлы `vcpkg.json`, `external/CMakeLists.txt`, `miniz`, `cli11`, `ddspp` совпадают с апстримом того периода. Поэтому взят коммит `5ded8c7` (2026-07-24). Свежий master не подходит: там уже другая файловая система (std::filesystem вместо Boost) и новые версии зависимостей. Это вывод по совпадению файлов, а не по записи самого Plus. Если сборка упадёт на несовпадении API, первым делом проверять версии `dynarmic`, `sdl`, `ffmpeg`.

## PKGj: только PSV игры и DLC

Исходник PKGj v0.61 это `blastrock/pkgj` (коммит `bf74686`). Патч `pkgj/0001-only-vita-games-and-dlcs.patch` убирает из браузера PSV Themes, Demos, PSM, PSP, PSP DLC и PS1, а при «Refresh» PKGj скачивает только списки игр и DLC (раньше 8 списков).

Workflow `Build PKGj` собирает патченый `pkgj.vpk` (VitaSDK через Conan), кладёт его в `android/app/assets/preinstalled/` и запускает сборку APK. Эмулятор переустанавливает встроенный PKGj, когда файл `pkgj.version` меняется.

Патч `pkgj/0002-direct-install-no-media-no-flags.patch`: игры и DLC скачиваются напрямую и ставятся через `scePromoterUtility` (в v0.61 они по умолчанию уходят в очередь LiveArea через закрытую службу `SceShellSvc`, которой в эмуляторе нет, из-за чего PKGj падал на нулевом адресе). Также убраны обложка, скриншоты, описание и Flag.

Патч `pkgj/0003-downloads-screen.patch`: экран «Загрузки» (идёт загрузка, очередь, последние 20 результатов). Открывается кнопкой □ в списке игр на месте убранного Flag; ✕ отменяет выбранную загрузку, ○ закрывает. В списке DLC кнопка □ по-прежнему выбирает несколько DLC.

Патч `pkgj/0004-game-and-dlc-install-menu.patch`: в карточке игры кнопка Install открывает меню. Игра не установлена: «Game only / Game + all DLC (N) / Cancel» (без DLC: «Game / Cancel»). Игра установлена и есть неустановленные DLC: «Download DLC (N) / Redownload game / Cancel». В списке DLC убраны кнопка □ и мультивыбор, □ работает только в списке игр (экран «Загрузки»).

Эмулятор теперь отдаёт версию прошивки 3.74 (`sceKernelGetSystemSwVersion`, `_vshSblGetSystemSwVersion`), а проверка существования файла (`stat`) больше не пишет ошибки в лог (PKGj проверяет `.resume` для каждой игры списка).

## Установка новых сборок поверх старых

Раньше каждая CI-сборка получала случайный debug-ключ, поэтому Android не давал поставить новый APK поверх старого («Приложение не установлено») и приходилось удалять эмулятор вместе с данными.

Теперь APK подписывается постоянным ключом `android/app/fixed-debug.keystore` (это открытый debug-ключ, пароль `android`; он нужен только для обновлений, не для безопасности). Все сборки, начиная с этой, ставятся как **обновление** и сохраняют прошивку, игры и настройки.

**Один раз** придётся удалить сборку, установленную до этого изменения (она подписана другим ключом). Перед удалением скопируйте папку данных `Android/data/org.vita3kplus.emulator.debug/files`, если там есть что сохранять.

## Ускорение CI

Сделано сразу:
- CI запускается по пушу, но не при изменении `*.md`, `docs/`, `_readme/`.
- Только **один job: Android arm64-v8a**. Убраны Windows, Linux, macOS, CodeQL, format и labeler.
- **Только arm64-v8a**, без x86/x86_64 (на уровне Gradle это уже было).
- `fetch-depth: 1` (без истории).
- Кэш vcpkg-зависимостей и ccache (до 2 ГБ), кэш Gradle.
- `concurrency` с `cancel-in-progress`: новый пуш отменяет предыдущую сборку.
- Без ключа подписи собирается `Reldebug`: для тестов подпись не нужна.

Оценка по факту (риски):

- **ccache**: подключён как compiler launcher, только в CI (раньше ccache-action не действовал: компилятор NDK не в `PATH`). Риск минимальный, ускоряет повторные сборки.
- **Tracy** (профилировщик) в Reldebug выключен (`TRACY_ENABLE_ON_CORE_COMPONENTS=OFF`). Это тот же режим, в котором уже собирается Release. Риск минимальный, плюс небольшое ускорение эмуляции на телефоне.
- **Не делаем**: отключение googletest и gdbstub. Это крошечные части сборки, выигрыш незаметен, а риск сломать линковку не нулевой.

## Правила работы

- Один шаг плана, один (или несколько) коммитов.
- Перед каждым шагом отмечать выполненное галочками в этом файле.
- Все правки эмулятора живут в `vita3k/` в этом репозитории.
